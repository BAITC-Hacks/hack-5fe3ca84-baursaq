## Git без конфликтов
Azamat: `git switch -c codex/ui origin/codex/career-quest-foundation`.

Umar: `git switch -c codex/agent origin/codex/career-quest-foundation`.

Каждый работает со своей копией и веткой, делает коммит и `git push -u origin <ветка>`. Первый push через 20–30 минут, затем каждые 20–30 минут. Обмениваться ссылкой на ветку/коммит и кратким статусом. Не ждать финала для первой интеграции.

Aniyar получает ветки, запускает проверки, последовательно сливает `origin/codex/agent` и `origin/codex/ui` в `codex/career-quest-foundation` с сохранением авторских коммитов (`git merge --no-ff ...`). При конфликте контрактов решает интегратор. После приёмки команда переносит общую ветку в main для сдачи. Не делать squash чужих изменений и не подписывать их чужим именем.

Журнал `docs/contributions/<имя>.md`: задача → что реализовано → как проверено → hash коммита при наличии. Это помогает объяснить фактический вклад каждого, но не заменяет рабочие изменения и не гарантирует решение жюри.

## Бюджет и модели
Pro/Codex — для написания и проверки кода каждым участником. API — для работы продукта. В исследовании есть неподтверждённые утверждения о моделях, ценах и обязательном публичном хостинге; не используем их как правила. Официальная инструкция требует репозиторий, AI-агента и сдачу на платформе; ссылку на deployed-версию указывают, если она есть.

Стартовый ориентир расходов команды на разработку: $5–10 API, с проверкой фактического расхода в кабинете. Не включать автоматические массовые прогоны на 200 сотрудниках. Три трудных профиля и 5–10 ручных проверок полезнее. Остальные кредиты держать для защиты. Название рабочей API-модели проверяет Umar, оно задаётся в `.env`.

По решению команды основная проверка будет через репозиторий. Публичный хостинг сейчас не входит в объём; освобождённое время уходит на чистый запуск, тесты и README. Исходный код должен быть в main к финальной сдаче.
