# Career Quest: правила совместной разработки

Цель: за 3 часа собрать проверяемый Career Quest на выданном датасете. Ядро — объяснимый выбор 1–3 активностей по нескольким факторам и обновление прогресса. Код создаётся с AI-агентами; каждый человек проверяет и коммитит свою часть под собственным аккаунтом.

## Правила предметной области
- Сегодня в датасете: **2026-10-01**, не системная дата.
- Навык отсутствует => 0. После `last_review_date` применить завершённые активности в хронологическом порядке, до даты среза включительно.
- Прирост: `max(current, min(5, max_level, current + gain))`; никогда не снижать навык.
- Не рекомендовать mandatory, недоступную роль/грейд, невыполненные prerequisites, уже завершённое мероприятие (кроме EV_036), мероприятия без будущих сессий (кроме self_paced).
- Учитывать career_goal, critical_skills, историю отказов/пропусков/завершений. Не сводить рекомендацию к минимальному навыку.
- Прогресс — покрытие требований выбранной цели, не вероятность повышения. Lead без новой цели получает развитие в текущей роли.
- LLM выбирает только из проверенных кандидатов. Числа, права и изменения прогресса контролирует Python.
- Нет скрытой подмены AI: резервный результат имеет `mode=rules`, ошибки/таймаут видны. Нет записанного демо вместо реальной обработки.
- Нет публичного рейтинга сотрудников; HR-данные доступны только HR. Никогда не помещать API-ключи в Git.

## Работа
- Ветки: `codex/ui`, `codex/agent`, `codex/career-quest-foundation` (интеграция). Общая исходная база — опубликованный каркас в `origin/codex/career-quest-foundation`.
- Перед работой: `git fetch origin`, затем создать свою ветку от общей базы. Не делать force push, не коммитить от имени коллег.
- Небольшие осмысленные коммиты; первый push через 20–30 минут. Слияние в main выполняет Aniyar.
- Backend: Python 3.11+, FastAPI. Frontend: React + TypeScript + Vite. Один backend отдаёт собранный frontend.
- Проверки: `python -m pytest -q`; frontend: `npm --prefix frontend run build`.
- Документировать фактический результат и ограничения. Research — справочный материал; официальное ТЗ и README датасета приоритетнее.
- Не добавлять RAG/векторную БД, микросервисы, валюту, чат общего назначения, обучение моделей или интеграции календаря в обязательный объём.
