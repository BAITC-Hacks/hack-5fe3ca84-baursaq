## 1. МИССИЯ И DEFINITION OF DONE
Мы за ~5 часов строим РАБОТАЮЩЕЕ agentic-AI решение под одну из 10 отраслевых задач,
раскрываемых на месте. Побеждает не самый сложный код, а самое убедительное РАБОТАЮЩЕЕ демо.

DONE = всё нижеперечисленное одновременно:
- [ ] Есть развёрнутый публичный линк (frontend + backend живые), открывается с телефона жюри.
- [ ] Основной happy-path сценария проходит от начала до конца без падений.
- [ ] Внутри реально работает агентная логика на OpenAI API + Codex использовался в разработке.
- [ ] Есть 90-секундный сценарий демо, отрепетированный вслух минимум 1 раз.
- [ ] Линк остаётся живым 24–28 сентября (jury review) — см. раздел 5.

НЕ DONE (не тратим время): auth-система, регистрация юзеров, платежи, адаптив под все экраны,
100% покрытие тестами, микросервисы, Kubernetes, красивый код ради красоты.

## 2. ПРИОРИТЕТЫ ЖЮРИ (по важности — на это оптимизируем каждое решение)
1. РАБОТАЮЩЕЕ ДЕМО — если падает на сцене, всё остальное не считается.
2. ЯСНАЯ ПРОБЛЕМА — жюри за 15 секунд понимает, чью боль и как мы решаем.
3. AGENTIC AI — видно, что ИИ рассуждает/планирует/вызывает инструменты, а не просто чат-обёртка.
4. UX — чисто, быстро, понятно; один экран, который «продаёт».
5. BUSINESS VALUE — кто заплатит/внедрит, какой эффект (цифра, пусть даже оценочная).
6. ЗАЩИТА НА DEMO DAY (29.09) — кто и что говорит, отрепетировано.

## 3. ЖЁСТКИЕ ПРАВИЛА (нарушение = дисквалификация или потеря очков)
- РАЗРЕШЁН только заранее собранный УНИВЕРСАЛЬНЫЙ технический harness БЕЗ бизнес-логики задачи.
  Никакого заранее написанного кода под конкретную задачу до её раскрытия. Harness = каркас:
  FastAPI-скелет, health-check, роутинг моделей, подключение БД, пустой React-шаблон, CI-деплой.
- Codex ОБЯЗАТЕЛЬНО используется в процессе разработки (сохраняйте историю/скриншоты промптов).
- OpenAI API ОБЯЗАТЕЛЕН как один из компонентов решения.
- Развёрнутый линк должен оставаться ЖИВЫМ 24–28 сентября. Хостинг выбираем без «засыпания»
  (Neon БД не паузится; backend — Render/Fly, следим чтобы инстанс не спал; иначе — платный
  минимальный тариф на неделю или keep-alive пинг каждые 5 минут).
- Другие AI-сервисы разрешены (Claude, NVIDIA NIM, Gemini и т.д.) — используем свободно.

## 4. РУБРИКА ВЫБОРА ЗАДАЧИ (сразу после раскрытия — таймбокс 20 минут)
Известные треки: строительство, госуслуги, образование, финтех, здравоохранение,
сельское хозяйство (+ ещё 4). Оцениваем КАЖДУЮ доступную задачу по 5 критериям, 1–5 баллов:

| Критерий | Вес |
|---|---|
| A. Можем ли сделать РАБОТАЮЩЕЕ демо за ~4 часа? (реалистичность scope) | ×3 |
| B. Есть ли готовый актив/опыт? (казах. словарный тренажёр со spaced repetition + произношение уже есть) | ×2 |
| C. Насколько ярко ложится agentic-AI (планирование, инструменты, RAG)? | ×2 |
| D. Понятная боль + business value | ×2 |
| E. «Вау» на демо (речь/голос/казахский — сильный визуальный/эмоц. эффект) | ×1 |

ПРЕДПОЧТЕНИЕ: задача на КАЗАХСКОМ ЯЗЫКЕ, желательно трек ОБРАЗОВАНИЕ
(изучение казахского, тьютор, оценивание, речь/произношение) — там у нас готовый актив
и «национальная» история, которая резонирует с жюри и спонсорами.
НО: если другая задача набирает больше баллов по таблице — берём её. Считаем честно.
Решение фиксируем письменно в разделе 8 и больше не пересматриваем.

## 5. ТАЙМ-ЧЕКПОИНТЫ (~5 часов) С GO/NO-GO ГЕЙТАМИ
T+0:00  Задача раскрыта. Выбор задачи по рубрике (20 мин). Пишем problem/user/metric (раздел 9).
T+0:30  GATE-1: зафиксированы scope, 1 главный happy-path, роли. NO-GO → режем фичи.
T+1:00  Скелет работает end-to-end на МОКах (frontend дергает backend, возвращается заглушка).
T+2:00  GATE-2: реальный AI-вызов проходит хотя бы 1 раз (не мок). NO-GO → упрощаем агента до 1 шага.
T+3:00  Happy-path целиком на реальных данных. Начинаем деплой (не в последний момент!).
T+3:30  GATE-3: публичный линк открывается со стороннего устройства. NO-GO → чиним деплой, стоп-фичи.
T+4:00  FREEZE фич. Только багфиксы + наполнение демо-данными + polish экрана.
T+4:30  Прогон демо вслух (90 сек). Скрин-рекординг как бэкап (Loom/Screen Studio).
T+5:00  Сабмит. Линк, репозиторий, описание.

ПРОТОКОЛ РЕЗКИ SCOPE (когда не успеваем — применять без сожаления):
1) Убираем вторую фичу, оставляем ОДИН сценарий.  2) Заменяем реальный компонент моком
(демо-надёжность > полнота).  3) Хардкодим демо-данные.  4) Убираем запись в БД, читаем из seed.
5) Один экран вместо трёх. Всегда сохраняем: рабочий линк + happy-path + agentic-момент.

## 7. КОНВЕНЦИИ ДЛЯ AI-АГЕНТОВ (Codex / Claude — читать перед генерацией)
СТЕК: Python 3.11 + FastAPI + Pydantic v2, менеджер пакетов `uv`. Frontend React+TS на Vite.
БД PostgreSQL + pgvector (Neon). LLM через OpenAI SDK.
СТРУКТУРА ПАПОК:
  /backend   app/main.py (FastAPI), app/agents/, app/routers/, app/services/, app/models/,
             app/mocks/ (заглушки для демо), .env.example
  /frontend  src/ (Vite React TS), src/components/, src/api/
  /AGENTS.md (этот файл)  /README.md (как запустить)
КАК ЗАПУСКАТЬ/ТЕСТИТЬ:
  backend:  `uv sync && uv run uvicorn app.main:app --reload`
  frontend: `npm i && npm run dev`
  быстрый тест: `uv run pytest -q` (только smoke-тесты happy-path, не гонитесь за coverage)
ПРАВИЛА КОДА:
  - НЕ over-engineer. Минимум абстракций. Один модуль — одна ответственность.
  - Все внешние вызовы (LLM, речь) — через app/services/ с таймаутом и fallback на app/mocks/.
  - Для ДЕМО-НАДЁЖНОСТИ: любой сетевой вызов имеет мок-переключатель через env
    (`USE_MOCKS=true`), чтобы демо не падало от сети/лимитов.
  - Логировать каждый LLM-вызов: модель, токены in/out, оценочная стоимость, latency.
  - Секреты только из .env, никогда в коде/гите. Коммить .env.example без значений.
  - Пиши осмысленные commit-сообщения (пригодится доказать использование Codex).

## 10. MODEL ROUTING (какую модель на какую задачу)
- ОСНОВНОЙ reasoning/агент: флагман OpenAI (GPT-5-семейство/новейший доступный) через Agents SDK.
- ДЁШЕВО/БЫСТРО (классификация, короткие шаги, парсинг): OpenAI mini-модель.
- FALLBACK при лимитах/сбое OpenAI: NVIDIA NIM (`integrate.api.nvidia.com/v1`, OpenAI-совместимо)
  или Google Gemini Flash (щедрый free tier). Groq — если нужен очень быстрый ответ на open-моделях.
- ВЕРИФИКАЦИЯ КАЗАХСКОГО: если критично качество казахского текста — прогнать вывод через
  вторую модель (Claude или GPT) как «редактора-носителя»; для фактов — RAG (см. раздел 11).
- ПРАВИЛО: сначала самый дешёвый маршрут, эскалация к флагману только если качество не проходит.
  Всегда таймаут и мок-fallback (демо-надёжность важнее «настоящности»).

## 11. KAZAKH-ГАЙД (что реально работает для казахского)
ТЕКСТ/LLM:
- Лучший результат в казахском сегодня дают проприетарные модели: GPT-4o = 76.90% на KazMMLU —
  лучший результат среди 27 протестированных моделей (Togmanov et al., ACL 2025, arXiv:2502.12829).
  При англ. промптах лидируют DeepSeek V3 (76.9%) и GPT-4o (76.6%).
- КЛЮЧЕВОЙ ПРИЁМ: RAG резко закрывает разрыв. KazLLM-8B без контекста 0.427 → с идеальным RAG 0.867
  (почти уровень GPT-4o 0.869); в end-to-end RAG KazLLM-8B+Snowflake достиг 0.754, обогнав лучший
  результат GPT-4o 0.632 (Information 2025, 16(11):943). ВЫВОД: для казахских фактов/контента —
  всегда RAG на казахских источниках (pgvector), генерацию доверяем флагману OpenAI.
- ISSAI KAZ-LLM (8B/70B, HuggingFace `issai/LLama-3.1-KazLLM-1.0-70B`, лицензия CC BY-NC 4.0  —
  НЕкоммерческая!) — использовать как «национальную фишку» в питче; хостить 70B за 5 часов дорого,
  реалистичнее 8B или просто упомянуть/сравнить.
РЕЧЬ (STT/TTS):
- STT: GPT-4o-transcribe / gpt-transcribe (робастнее «сырого» Whisper на казахском). У Whisper-large
  без дообучения WER на казахском ~43.58% на Fleurs-test и >55% на KSC (arXiv:2408.05554); дообучение
  на казахском снижает WER radикально (43.20% generic → 11.88% fine-tuned, Information 2026, 17(7):690).
  ElevenLabs Scribe поддерживает казахский STT. ISSAI Soyle — специализированный казахский ASR
  (Whisper-подобный, шумоустойчивый, CC BY 4.0) — сильная «локальная» история.
- TTS: ElevenLabs (казахский поддержан, Eleven v3, код kaz)  — самый быстрый путь к качественному
  голосу. ISSAI KazakhTTS2 / KazEmoTTS (эмоции) / KazGenericTTS — открытые, для «сделано в Казахстане».
- Yandex SpeechKit — казахский STT (модели general/general:rc, стриминг + пунктуатор),  но платный и
  есть риск доступности оплаты; для хакатона второстепенно.
ПРАВИЛО ДЕМО: заранее подготовить 2–3 «золотых» казахских аудио/текст-примера, на которых всё точно
работает, и на них строить демо (мок-фолбэк на случай сети).
