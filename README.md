# Career Quest · baursaq

Навигатор развития сотрудника: профиль и карьерная цель → объяснимые следующие шаги → выполнение активности → обновлённые навыки. HR видит дефициты компетенций и сотрудников без подходящего шага.

**Статус: рабочая основа MVP, не финальная AI-версия.** Подбор сейчас выполняется по явно обозначенным правилам. Настоящий OpenAI-агент — отдельная задача Umar, финальный UI — зона Azamat. Наличие API-ключа само по себе не включает AI в текущем каркасе.

## Что реализовано

- Выданный набор: 200 профилей, 40 событий, 60 навыков, 2 743 записи истории.
- Профиль, цель, история, покрытие требований и критичные навыки.
- Пересчёт навыков с учётом завершений после последней оценки.
- Фильтрация mandatory, роли/грейда, prerequisites, завершённых событий и доступных дат.
- Резервные рекомендации по нескольким факторам с объяснением и прогнозом прироста.
- Завершение активности, SQLite и защита от повторного начисления.
- HR: частые разрывы, отсутствие доступного шага, участие по событиям.
- Импорт JSON профилей и CSV истории жюри с валидацией и атомарной записью.
- Серверное разграничение employee/HR; демо-сессии на 8 часов.
- Базовый React-интерфейс, Swagger, тесты, GitHub Actions.

## Запуск одной командой

Нужны Python **3.11+** и Node.js **22+** с npm. Из корня:

```bash
python run.py --setup
```

Команда создаст `.venv`, установит зависимости, соберёт frontend и запустит **http://127.0.0.1:8000**. Интернет нужен при первой установке. Далее: `python run.py`. После изменений UI: `python run.py --build`. Если Python называется `python3`, замените имя команды.

Альтернатива при наличии Docker:

```bash
docker compose up --build
```

Docker-конфигурация подготовлена; проверка контейнера отмечается отдельно от локальной сборки. База хранится в `.state/` либо в Docker volume. Не удаляйте её, если нужно сохранить прогресс.

## Сценарий проверки

1. Войдите как **E0001 / Marat Yessenov**, пароль `employee-demo`.
2. Проверьте роль, цель и навыки. На исходном наборе покрытие цели — **54,5%**.
3. Нажмите «Подобрать шаги». Каркас покажет режим «Подбор по правилам», объяснение через цель, разрыв и историю, прогноз изменения навыков.
4. Отметьте активность выполненной. Прогресс обновится; повторный запрос не начислит прирост снова. Исходные JSON/CSV не меняются.
5. Выйдите и войдите как HR, пароль `hr-demo`. Откройте обзор: агрегаты, участие и сотрудники без шага. На исходном наборе таких сотрудников **34**; после импорта/выполнений число может измениться.
6. Загрузите дополнительные профили JSON и CSV истории в HR. Выберите новый профиль и запросите рекомендации.
7. После интеграции Umar отдельно проверьте `mode=openai`, реальные вызовы инструментов в trace и три трудных профиля. Резервный режим эту проверку не заменяет.

Схемы API: http://127.0.0.1:8000/docs. [Контракт команды](docs/API.md).

## Тесты и разработка

После setup, Windows:

```powershell
.venv\Scripts\python.exe -m pytest -q
npm --prefix frontend run build
```

Linux/macOS: `.venv/bin/python -m pytest -q`.

Для разработки — два терминала, первый с активированным `.venv`:

```bash
python -m uvicorn backend.app.main:app --reload --port 8000
npm --prefix frontend run dev
```

Vite проксирует `/api` на backend. Тестируются прирост/cap, история после review, идемпотентность, ограничения каталога, влияние истории, импорт и права. Эти тесты не измеряют качество ещё не подключённой LLM.

Проверка каркаса на Windows: установка в чистую `.venv` и запуск одной командой прошли; production-сборка прошла; браузерный путь E0001 → подбор → завершение повысил покрытие цели с 54,5% до 60,6%. Docker-образ не запускался.

## Технологии и архитектура

Python/FastAPI/Pydantic, SQLite, React/TypeScript/Vite. Зависимости закреплены в `requirements.txt` и `frontend/package-lock.json`.

```text
React → FastAPI → Domain → SQLite ← исходные JSON/CSV
             └→ agent/service.py → будущий OpenAI tool loop
```

Python вычисляет ограничения и числа. AI-агент должен выбирать допустимые шаги через read-only инструменты и объяснять компромиссы. Завершение требует явного действия пользователя. [Архитектура](docs/ARCHITECTURE.md), [план на 180 минут](docs/TEAM_PLAN.md).

## Данные и внешние сервисы

[Правила датасета](career_quest_dataset/case_1/career_quest_dataset/README.ru.md). Дата среза — **2026-10-01**. Отсутствующий навык равен 0. Завершение применяет `gain` до `max_level`, не снижая более высокий уровень. EV_036 допускает повторения, в демо — одно начисление в дату среза.

Резервное ранжирование: закрываемый разрыв × 3 для критичного навыка; поправка на пропуски/отказы сходных мероприятий и удалённую работу при очной активности. Это эвристика, не обученная модель. Покрытие цели — доля удовлетворённых уровней требований, не вероятность повышения.

В текущем каркасе внешние AI API **не вызываются**. Для будущей AI-части скопируйте `.env.example` в `.env` и локально заполните `OPENAI_API_KEY` и проверенный `OPENAI_MODEL`. Ключи не попадают в браузер/Git. Протокол: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling).

## Ограничения

- OpenAI tool loop и реальные evals ещё предстоит добавить Umar. Без них ТЗ полностью не выполнено.
- UI базовый; финальная доработка и UX принадлежат Azamat.
- Демо-пароли всем известны; это не промышленный SSO, используются вымышленные личности.
- Один процесс backend. Сессии исчезают после перезапуска, SQLite сохраняется.
- UI на русском, названия событий/навыков из английского набора; полной локализации нет.
- При замене профиля импорт сбрасывает его локальные демо-завершения. Отсутствующие CSV строки существующей истории не удаляются.
- Публичного deployed URL нет: команда выбрала проверку через репозиторий.
