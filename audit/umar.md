# Аудит README и воспроизводимости — Umar

Дата проверки: 23 сентября 2026 года.

Проверялся свежий клон с GitHub, коммит `40e7e10`, на macOS 26.5.2, Apple Silicon. Ключи из рабочего проекта не переносились. Исходный код и документация при аудите не изменялись.

Окружение: Python 3.13.5, Node.js 24.13.0, npm 11.6.2, Docker CLI 29.1.3, Compose 2.40.3. После первоначальных попыток uv 0.12.18 был установлен в отдельное временное окружение.

## Оценка

Моя экспертная оценка — **20/25 за README и воспроизводимость**. Это оценка аудитора, не официальный результат жюри. Проект действительно запускается, основные сценарии работают. Баллы теряются на неточностях инструкции и недостатке проверяемых доказательств реального AI.

## Заминки по важности

1. **Неверно указан минимум Node.js.** В README — `Node.js 22+`, но установленный Vite требует `^20.19.0 || >=22.12.0`. Проверяющий с Node 22.0 формально выполнил инструкцию, но оказался вне поддерживаемого диапазона. Лучше указать **Node.js ≥22.12**. Проверка на Node 22.0 не запускалась: несовпадение установлено по `frontend/package-lock.json`.
2. **Локальный запуск на другом порту и eval не связаны инструкцией.** Launcher работает на 8011, а eval по умолчанию обращается на 8000. Воспроизведено: после остановки Docker обычный eval выдаёт `ERROR: <urlopen error [Errno 61] Connection refused>` с кодом 2, хотя приложение на 8011 продолжает работать. Нужна рядом команда `python scripts/eval_profiles.py --base-url http://127.0.0.1:8011`. Флаг описан в связанном `data/test_profiles/EXPECTED.md`, но в основном README его приходится искать.
3. **На этой macOS команда `python` отсутствует.** Нужна оговорка «на macOS/Linux используйте `python3`, если `python` отсутствует», плюс ссылка или инструкция установки uv. Сейчас launcher при отсутствии uv перечисляет требования, но не объясняет следующий шаг.
4. **Неочевидна организация терминалов.** Docker и launcher занимают терминал. Для eval нужен другой терминал в корне. В блоке проверок перемешаны команды из корня, `backend` и отдельного терминала для `frontend`. Комментарий про фронтенд есть, однако копирование всего блока подряд сломается. Лучше отдельные блоки с явно указанными каталогами.
5. **В сценарии импорта не названы два файла.** «Загрузить два файла из `data/test_profiles/`» заставляет заглядывать в папку и выбирать. Там также лежит `EXPECTED.md`. Следует прямо назвать `employees.json` и `activity_history.csv`, попросить выбрать оба одновременно.
6. **Не задан ожидаемый результат контрольного сценария.** Для fallback стоит написать: E0072 начинает с **53%**, первый шаг — **API & Performance Testing Workshop**, после завершения — **59%**. Тогда проверяющий сразу понимает, что получил правильный результат. Для LLM нужно отдельно предупредить, что выбор может отличаться.

### Скоринг

Числовые коэффициенты во всех строках таблицы совпадают с движком. Но три формулировки недостаточно точны:

- `+0.3` за «добровольное завершение» фактически требует **`assigned_by=self`**. Завершённое необязательное мероприятие, назначенное менеджером, этого бонуса не получает.
- `+0.2` за рост вне требований применяется, когда прирост данного навыка **вообще не закрывает разрыв** текущего или целевого грейда. Это не отдельный бонус за каждый «лишний» уровень поверх закрытого разрыва.
- Штраф за похожие мероприятия берётся по навыку с **максимальным числом срывов**, а не суммируется по всем развиваемым навыкам.

Проверяемые места: `history_signals` и `score_event` в `backend/app/services/engine.py`.

Вводное «предлагает 1–3 шага» стоит уточнить: **до трёх, а при отсутствии полезных вариантов — ноль с объяснением**. Именно так правильно работает T005.

Для T001 fallback выбрал `EV_006 → EV_007 → EV_010`, готовность 61% → 75% по плану. Для E0028 текущая готовность 73%, предложен один шаг `EV_037` с прогнозом 75%.

Перед браузерной загрузкой eval уже добавил T-профили в тот же процесс, поэтому браузерный импорт проверял обновление существующих T-профилей. Первичное добавление было проверено HTTP eval на исходном состоянии обоих серверов.

Функционально сценарий проходит. **Укладка человека в 90 секунд не подтверждена**: проводился аудит с чтением результатов. Сценарий требует предварительно запущенного приложения и подготовленных файлов — это стоит написать в заголовке.
